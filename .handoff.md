## High-severity review items honored

1. **§4 server-first dual-tier check** — `_runCheck` issues `http.Request('GET', _uri)..followRedirects = false`, drains the body, treats 2xx as healthy. Falls through on TimeoutException / SocketException / http.ClientException / any Object. Disambiguation: `_internetChecker.hasInternetAccess` (correct symbol for `internet_connection_checker_plus` ^3.0.0; verified by reading `~/.pub-cache/.../lib/src/internet_connection.dart` line 217).
2. **§7 split `stop()` / `dispose()`** — `stop` cancels the timer + sets `_running = false`, leaves the controller open and never touches `_httpClient`. `dispose` cancels the timer, awaits `_controller.close()`, then conditionally `_httpClient.close()` only when `_ownsClient`. `dispose` is idempotent (returns early on second call); other methods after `dispose` throw `StateError`.
3. **§8 backgrounding rule** — already present in class dartdoc from ST-1; ST-2 does not change it.

## Medium items also covered

- **§3 ±10% jitter** — `_nextDelay` applies `jitterMs = base * jitterRatio * (rand*2 - 1)`. Supports `jitterRatio = 0` to disable. Negative result clamped to 0.
- **§6 `checkNow` Option B** — returns the state, does NOT call `_emitIfChanged` or `_controller.add`. Updates `_currentState`. Cancels the pending timer and reschedules only if `_running` (so a manual probe on a stopped monitor doesn't restart it).
- **§7 in-flight guards** — `_loop` checks `!_running || _disposed` BOTH at entry AND after `await _runCheck()`, before `_emitIfChanged` and before scheduling the next timer.
- **§4 followRedirects=false + 3xx** — set on the request; 3xx is not 2xx, so it falls through to the disambiguation block and resolves as `serverUnreachable` (since CDN probe will succeed in that scenario).
- **GET, not HEAD** — `http.Request('GET', _uri)`.
- **Body drained** — `await res.stream.drain<void>()` after each response to free the pooled connection.
